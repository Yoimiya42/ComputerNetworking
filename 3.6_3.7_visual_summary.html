3.6

拥塞控制原理 (Principles of Congestion Control)

🔑 核心概念

拥塞 = 网络中有太多发送者以过高速率发送数据，导致路由器缓存溢出、分组丢失与延迟剧增。 拥塞控制的目标是限制发送速率，以避免或恢复网络拥塞状态。

3.6.1 拥塞的代价与原因（三种场景）
场景 1
两个发送方 · 路由器无限缓存 发送速率趋近链路容量 R/2 时，排队延迟趋向无穷大。吞吐量上限 = R/2，但代价是极长时延。
💸 代价：大量排队延迟
场景 2
两个发送方 · 路由器有限缓存（含重传） 缓存溢出导致丢包，发送方必须重传。即使没有超时提前重传时，有效吞吐也低于 R/2，代价是带宽被重传浪费。
💸 代价：重传浪费带宽 💸 不必要的重传进一步降低吞吐
场景 3
四个发送方 · 有限缓存 · 多跳路径 高负载时，上游路由器转发的分组在下游被丢弃，上游占用的带宽全部白费。当负载趋向无穷，端到端吞吐趋向 0。
💸 代价：上游传输能力被浪费（工作无用化）
3.6.2 拥塞控制的两种方法

🔁 端到端拥塞控制

  • 网络层不提供显式反馈
  • 端系统通过观察丢包（超时 / 3×重复 ACK）或时延自行推断拥塞
  • TCP 采用此方式（Classic TCP）
TCP RenoTCP CUBIC

📣 网络辅助拥塞控制

  • 路由器显式通知发送/接收方拥塞状态
  • 方式 ①：路由器直接发送阻塞包给发送方
  • 方式 ②：在流经的数据包中标记拥塞位，由接收方通知发送方
ATM ABRECN (RFC 3168)
3.7

TCP 拥塞控制 (TCP Congestion Control)

3.7.1 经典 TCP 拥塞控制

🪟 拥塞窗口 cwnd

TCP 发送方用 cwnd（拥塞窗口）限制发送速率：

LastByteSent − LastByteAcked ≤ min(cwnd, rwnd)

发送速率 ≈ cwnd / RTT（字节/秒）
通过调整 cwnd 即可控制发送速率。

📡 拥塞感知方式

  • 超时：严重拥塞信号
  • 3×重复 ACK：轻度拥塞（快速重传）
  • 无丢包 ACK 到达：网络畅通 → 增大 cwnd

TCP 是 self-clocking：ACK 到达速率隐式反映了网络状态。

⚙️ 三阶段拥塞控制算法

🚀 慢启动 (Slow Start)

  • 初始 cwnd = 1 MSS
  • 每收到一个 ACK → cwnd += 1 MSS
  • 每 RTT 翻倍（指数增长）
  • 直到 cwnd ≥ ssthresh 或发生丢包
指数增长

📈 拥塞避免 (Congestion Avoidance)

  • cwnd ≥ ssthresh 时进入
  • 每 RTT cwnd += 1 MSS（线性增长）
  • 超时：ssthresh = cwnd/2，cwnd = 1
  • 3×重复 ACK：ssthresh = cwnd/2，cwnd = ssthresh（Reno）
线性增长 (AIMD)

⚡ 快速恢复 (Fast Recovery)

  • 仅 TCP Reno 推荐（非必须）
  • 3×重复 ACK 触发进入
  • cwnd = ssthresh + 3 MSS
  • 每个额外重复 ACK：cwnd += 1 MSS
  • 丢失包 ACK 到来 → 回到拥塞避免
  • 超时 → 回到慢启动
TCP Reno

📊 AIMD 锯齿波行为（TCP Reno 拥塞窗口示意）

平均吞吐量 = 0.75 × W / RTT   （W = 发生丢包时的窗口大小）
3.7.2 显式拥塞通知 (ECN) & 基于延迟的拥塞控制

🚦 显式拥塞通知 (ECN, RFC 3168)

  • 路由器在 IP 头部设置 ECN 位（2 bit，4 种值）
  • 接收方在 TCP ACK 中设置 ECE 位通知发送方
  • 发送方减半 cwnd，并设置 CWR 位
  • 优点：在丢包之前即可感知拥塞
ECN = 11（拥塞信号）ECE（Echo）

⏱️ 基于延迟的拥塞控制

  • TCP Vegas：测量 RTTmin，若实际吞吐 ≈ cwnd/RTTmin 则路径无拥塞，否则减速
  • BBR（Google B4 网络）：维持"管道满但不过满"，在丢包之前主动降速
  • 优点：避免不必要的包丢失与重传
TCP VegasBBR
3.7.3 公平性 (Fairness)

⚖️ AIMD 与公平性

若 K 条 TCP 连接共享瓶颈链路（容量 R），AIMD 算法会使每条连接的吞吐量收敛到 R/K。

两连接示意：吞吐量轨迹沿 45° 方向增加，达到 R 后减半，最终在"等带宽线"附近振荡收敛。

⚠️ 公平性挑战

  • UDP 应用：多媒体流不做拥塞控制，可能挤占 TCP 流量
  • 并行 TCP 连接：浏览器开多条 TCP 连接可获得不成比例的带宽（如 Web 页面加载）
